# 课程学习页面

## 启动和使用

继续双击根目录 `启动面板.bat`。已运行的旧版后端须重启一次，才能加载新增路由。
在原作业页面顶部点击“课程学习”，或访问 `http://127.0.0.1:8765/study`。
原作业页面的设置、基准测试、批量抓题、暂存和提交入口保留。

1. 点击“读取课程”，弹窗默认列出当前登录账号确认未完成的课程，显示任务点完成数。选择课程后自动填入平台生成的链接并读取任务。支持搜索、刷新列表及切换“状态未知 / 全部课程”；也可手动粘贴 `https://…chaoxing.com/mycourse/studentstudy?...` 链接，在弹窗点击“读取输入的链接”。
2. 课程列表、课程目录和任务读取默认使用无窗口浏览器，不抢焦点。点击“开始学习”或“打开课程窗口”才显示浏览器；切换显示模式前将当前 Cookie 和站点存储保存在内存，关闭旧实例后继承，不写入磁盘。已主动打开的窗口在再次读取时最小化，不关闭其中的表单。登录失效或无法解密时，可直接点击“打开课程窗口”手动登录，再读取课程；未读取课程时也可打开登录窗口。
3. 读取会进入各章节并检查可识别的学习步骤，分别列出带稳定编号的任务点。它不会因进入过章节而标记完成。
4. 读取后面板自动滚动到“学习设置”，读取过程中即可调整自动填写、自动提交、倍速等配置。读取完成后点击“开始学习”执行未完成任务，或选中任务后点击“开始选中任务”。读取本身不启动执行队列；课程浏览器在每个新文档中默认拦住视频和音频自动播放，仅显式执行的当前媒体允许播放。暂停后会撤销播放许可，阻止页面再次自动拉起。未知状态、锁定或无法识别的区域会显示原因。
5. 普通练习默认不开启自动填写、自动提交。开启后使用第一页的模型配置；自动提交已授权的普通练习不再逐题确认。
6. 限次或不可撤回的练习需要选中任务，并勾选单独授权。正式考试始终留给用户在原页面手动处理。发现考试步骤时不会自动点击进入。
7. 暂停后只有点击“继续”才恢复。恢复时重新进入目标章节及学习步骤、重新检查平台状态。停止会释放课程实例锁。
8. 需要人工处理时，任务行的“打开原页面”会暂停队列并定位到课程浏览器；可按选项暂停整个队列或继续其他可执行任务。
9. 页面刷新、执行结束或程序重启后，默认保留当前课程、已核验数、任务状态、设置和任务勾选。可直接开始或继续，不自动全量扫描；只有手动点击读取或刷新才扫描目录。执行时跳过历史明确核验完成的任务，只重新核验本次待执行任务，提交意图保护继续有效。重启后不会自行播放、请求模型或交卷。

账号在浏览器内登录，模型密钥仅用于后端模型请求。当前课程完整链接使用 Windows 当前用户 DPAPI 加密后保存在 `panel/study-data/courses.sqlite3`，任务快照仍只有脱敏链接；日志和导出不包含签名。账号课程列表中的其他链接只保留在内存。不会把 Cookie 或模型密钥加入课程缓存。旧版只有脱敏链接的记录，在用户第一次执行时仅恢复该课程入口及签名，沿用已有任务目录，不扫描整课；无法登录或课程身份不匹配时暂停提示。

## 实现与现有代码复用

- `panel/static/index.html` 仅增加第二页导航。
- `panel/static/study.html`、`study.js`、`study.css` 提供与原页面一致的蓝白界面、章节列表、操作开关、进度、状态和日志。
- 两页共用 `panel/static/header.css` 固定品牌区域宽度、导航间距和头部高度；小字和状态变化不移动导航，手机布局的导航统一位于第二行。
- `panel/app.py` 增加 `/study`、`/api/study`、`/api/study/courses`、`/api/study/load`、`/api/study/control`、`/api/study/export`。课程列表接口同样需要访问口令，并禁止浏览器缓存。
- `panel/study_directory.py` 复用课程浏览器的登录上下文，串行读取学生课程列表、章节页明确的“已完成任务点”计数及平台原生生成的学习链接。未捕获原生跳转时，仅对已知 `toOld` 结构读取页面当前参数还原链接，并核对课程和班级标识；不使用 `eval` 或硬编码会话值。列表读取时拦截学习页跳转，不进入播放器。未展示进度、零任务、目录不可访问等情形标记未知，不能判为已完成。课程列表采用有限滚动和原生分页；发现分页异常时提示列表可能不完整。
- 模型直接回调已有 `load_config()`、`call_llm()`。API 地址、模型、Bearer 认证、180 秒超时和原来的单次请求策略相同，不新增另一套模型设置。网络失败不自动重发提交请求。
- `panel/study_service.py` 是串行浏览器工作线程和状态机。暂停、停止、切课增加执行代次；旧模型结果、后续操作和退避等待检查代次，过期结果不进入填写或提交。
- 新执行流程也接入原 `new_job()`、`job_log()`、`job_done()`；课程日志另随恢复记录保存，并限制保留条数。
- `panel/study_browser.py` 复用 `lxt.launch_chromium()` 和 `lxt.load_cookies_for_browser()`。不修改第一页面原有浏览器行为。
- 课程浏览器通过新增的 `standard_automation=True` 选项使用标准自动化启动参数，不继承旧流程隐藏自动化标识的开关；原流程的默认参数保持兼容。
- `panel/study_dom.js` 读取目录、附件元数据、任务标记、题目及控件，不写入应用全局变量、不覆盖页面函数、不注入 CDN 脚本。
- `panel/study_questions.js` 共用题目提取与控件定位逻辑，兼容 `.singleQuesId`、自定义 `.num_option` 控件和阅读理解子题。选项通过页面正常点击填写，同时核对选中样式与平台隐藏答案字段；不直接写入隐藏字段。
- `panel/study_core.py` 负责链接校验、稳定标识、答案校验、脱敏、SQLite 记录和跨进程课程锁。
- 课程设置和任务选择修改后立即保存；刷新页面不会触发课程读取。继续执行时通过缓存链接按需建立浏览器，已完成任务直接沿用缓存；如需重新核对整课，请点击“刷新任务状态”。

## 平台数据与状态判定

适配器读取 `#coursetree` 下的稳定章节标识、学习步骤、`mArg.attachments`、`.ans-attach-ct` 和附件 iframe 数据。
任务键由课程、班级、可用的 cpi 的不可逆摘要及章节/任务编号产生；附件 objectid 与 jobid 合并，避免同一视频重复计数。
题目身份还包含题干、题型及选项摘要，题号或选项排列本身不作为唯一判断依据。

支持的执行状态包括待执行、准备中、执行中、等待模型、等待核验、暂停、完成、失败和需人工处理。
平台状态与执行状态分开。只有任务平台数据明确 `isPassed` 或任务区域明确显示完成，才计入已核验完成。
播放结束、填写控件、提交按钮被点击、HTTP 成功或页面提示“已保存”均不直接当作任务完成。

目录完整性采用保守策略：目录必须提供可核对的总章节数且没有未加载标记，才能确认完整。
不提供该信息的平台版本仍可执行已识别任务，但始终提示完整性未确认，不宣称课程全部完成。
锁定章节、没有稳定编号的区域以及受限入口会显示待解析条目，不冒充具体任务点计入总数。

视频执行器只有一个轮询完成入口，不注册第二套 ended 推进入口，因此不会由 ended 与轮询各切换一次。
动作结束先持久化，再等待 1、2、4 秒核验并重新读取页面。仍未确认时留为待核验，恢复时只核验，不重复播放。
页面节点每次重新定位；每个 frame 单独读取，某个 frame 失败不会让其他 frame 的查找直接中止。

浏览器内最多两个短暂播放尝试（含静音尝试），每次最多 3 秒，并清理其临时超时计时器。
后台没有无限重试、定时自动下一章或注入的长驻事件监听器。前端轮询在离开页面时取消；浏览器事件随上下文关闭清理。
播放中出现暂停不会一律强制恢复；弹题阻止普通播放逻辑，缓冲超过 45 秒或无真实进度超过 60 秒会提示。
播放速度限定 0.5～2 倍；只有平台菜单明确提供相应速度才使用，否则回退 1 倍。不能保证课程认可倍速学习记录。

## 提交与恢复

只支持已完整提取的单选、多选、判断和普通文本填空控件。模型结果必须精确匹配可用选项或空格数量；不接受自报置信度作为校验。
填写前后重新检查题目摘要并回读控件。控件状态不符、模型超时或页面变化时不提交。
提交前在 SQLite 写入提交意图；中断或超时后只核验，不能自动再点一次。若无法判断是否提交，请在原页面人工核对。
“已填写”“已保存”“已提交”“已判分”“任务完成”分别记录。开启自动提交后支持章节测验的 `#confirmSubWin` 确认流程；确认前再次检查题目，遇到未答题、验证拦截或未经授权的重要限制时暂停。未知对话框仍取消并暂停。

运行记录在 `panel/study-data/courses.sqlite3`，课程锁在 `panel/study-data/locks`。这些文件已被 Git 忽略。
记录不保存 Cookie、模型密钥或原始签名链接。日志不包含题目答案正文；导出再次清理已知认证字段、签名、手机号和邮箱。
课程标题等自由文本无法可靠识别所有人名，分享导出前仍需人工检查自由文本内容。

## 当前限制与人工接入

- 已对用户当前章节测验做真实页面只读验证：识别到“待完成”、15 道单选和阅读理解的 5 个子题，共 20 个答题单元。真实页面未填写、未提交；真实课程的完整提交链路仍未验收。第一页的 DeepSeek 模型连接测试通过。
- 平台有不同版本；当前适配器只自动处理能明确提取任务身份和状态的页面，不能保证所有课程目录/播放器版本都支持。
- 现有项目没有视觉模型/图片识别入口，包含图片、公式图、canvas 或无法读全的题目会明确转人工，不猜答案。
- 当前自动题目处理要求独立且明确的提交按钮。选择选项即提交的弹题、可疑的内联提交处理器和没有独立提交入口的题目交给人工，避免关闭自动提交后仍被页面事件间接提交。
- 文档和阅读只在页面显示可识别的阅读要求时正常翻页/滚动并等待平台状态，最多观察约 10 分钟。不知道要求、私有文档阅读器或不可访问资源时转人工；不会伪造计时或调用完成上报接口。
- 使用 Playwright 的独立浏览器上下文和逐 frame 操作；不会尝试绕过浏览器安全边界、验证码、身份验证或平台风控。无权限 frame、登录失效或验证拦截会给出原因。
- 页面脚本异常和网络失败会限频记录，不屏蔽报错；没有反检测保证，不修改 `eval`、`Function`、`console` 或全局计时器。
- 如果页面调试器或脚本令浏览器执行上下文长期阻塞，队列会显示工作线程响应异常；请关闭课程浏览器解除阻塞并重新读取。同步浏览器调用无法保证被暂停请求即时打断，但恢复后必须通过代次检查，旧任务不会自动继续。
- 已发出的模型 HTTP 请求不能从 requests 层强制取消；暂停会使响应失效，等待其超时或结束后才能再次请求，避免堆积调用。

Playwright 的 frame 和上下文机制参考官方文档：[Frames](https://playwright.dev/python/docs/frames)、[BrowserContext](https://playwright.dev/python/docs/api/class-browsercontext)、[操作前检查](https://playwright.dev/python/docs/actionability)。
